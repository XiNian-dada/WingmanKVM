# 系数域重压缩实验

与本目录的纯色像素块源码补丁分开测量。这里使用**未修改的安装库** libjpeg-turbo 2.1.5，处理 JPEG→JPEG：读出量化 DCT 系数，重新量化，再熵编码，省掉 IDCT、RGB 色彩往返和 FDCT。库已有这类 API，这条路线不是本项目发明；新增工作是零 AC 快捷路径及精确 NEON 重新量化内核。

代码：[requant.c](requant.c)、[requant_core.h](requant_core.h)。只处理程序自行生成的 1920×1080、8 位 sequential YCbCr、4:2:2、标准表输入，源质量 95、目标质量 81。保留源采样和尺寸。不是可供生产处理任意 JPEG 的公共解析器，也未接入服务。

## 算法

源系数 `c`、旧量化值 `old`、新量化值 `d`：

```text
n = abs(c) * old + floor(d/2)
new_magnitude = floor(n/d)
new_coefficient = sign(c) * new_magnitude
```

每项取 `d=max(target_quantizer,old)`，只降低精度，避免对较粗的源表假装恢复精度。输出量化表不一定等于通用“质量 81”表；本次标准 q95→q81 输入满足所有目标项均不小于旧表。

1. 若 63 个 AC 系数都等于零，完整检查后只重算 DC；它不要求源像素完全纯色，而是利用已读取的系数结构。
2. 其余块八路 NEON 处理。先扩展幅值、乘旧表并加半个新表，再用 `SQDMULH` 及 `r=ceil(2^31/d)` 估算商；若 `q*d>n` 减一。`d=1` 单独走恒等通道。
3. 保留负号及 `i16::MIN`。接受域是 `1≤old≤d≤255`、完整 i16 系数；`n≤8,355,967<2^24`，都是非负 i32，没有可达的饱和情形。

估商正确性的简短依据：`0≤r−2^31/d<1`，故 `0≤n*r/2^31−n/d<1`；估计商至多大一，一次比较修正即为精确整数除法。输出与标量系数算法字节一致，**不意味着降质量操作无损，也不意味着与原来的 RGB 重编码输出相同**。

64 位标量倒数方案也保留用于对照；它在多数图上比直接除法慢，不作为推荐实现。

## RK3399 结果

环境同 [README](README.md)，实际绑定 CPU 4、`nice -n 10`。安装库通过本任务的临时公共头文件调用，严格 `cc -O3 -Wall -Wextra -Werror` 编译通过。1 轮预热、15 轮计时；五种模式在同一进程轮换，所有缓冲预留，完整计入每帧解码/读取系数、转换、编码和对象创建销毁。输入生成和最后的画质测量在计时外。

| 合成输入 | 系统库 RGB 解码再编码 | 朴素标量系数路径 | 零 AC + NEON 系数路径 | 对 RGB 路径耗时变化 |
| --- | ---: | ---: | ---: | ---: |
| 纯色 | 39.736 ms | 31.361 ms | 23.895 ms | −39.9% |
| 稀疏终端 | 44.228 ms | 37.647 ms | 29.865 ms | −32.5% |
| 密集字符 | 74.511 ms | 70.910 ms | 63.182 ms | −15.2% |
| 渐变 | 49.913 ms | 42.692 ms | 39.951 ms | −20.0% |
| 噪声 | 124.181 ms | 132.240 ms | 112.316 ms | −9.6% |

因此不是只换 API 就必然更快：朴素系数算法在噪声图上反而更慢。新内核相对朴素系数路径减少约 6%～24% 的整帧耗时。纯色时 flat-only 模式为 23.750 ms，NEON 组合为 23.895 ms，均不会执行 AC 的向量量化；这种小差异不据此判断内核优劣。

但这也**不是同码率、同重建画质的胜负比较**。两条路径使用相同目标量化表及 4:2:2，产生不同像素和码流：

| 输入 | RGB 路径输出字节 | 系数路径输出字节 | RGB PSNR | 系数 PSNR |
| --- | ---: | ---: | ---: | ---: |
| 纯色 | 41,128 | 41,128 | ∞ | ∞ |
| 稀疏终端 | 129,811 | 135,091 | 40.674 dB | 41.218 dB |
| 密集字符 | 741,141 | 779,097 | 31.871 dB | 32.319 dB |
| 渐变 | 144,031 | 152,564 | 40.728 dB | 42.946 dB |
| 噪声 | 1,758,357 | 1,930,669 | 24.316 dB | 26.007 dB |

PSNR 参考是**源质量 95 JPEG 解码后的 RGB**，不是未压缩原图。系数路径保留源采样，避免 RGB 往返再次改变色度；此处体积增加约 4%～10%，PSNR 更高。纯色的无穷值仅表明该合成输入的解码像素相同，不能推广为重压缩无损。以后仍需做相同体积或相同画质下的参数扫描及真实文字可读性比较。

## 正确性与复现

`test` 在 ARM 真机上通过：完整 i16 系数域 × 255 种除数 × 三种代表性旧量化值（1、向上取整一半、原值），共 50,135,040 个系数；另有 10,000 组混合量化表、混合符号和非 16 字节对齐块。基准每轮断言全部四种系数实现的**完整 JPEG 字节一致**；最后解码检查尺寸并计算 PSNR。测试没有声称穷举全部旧/新量化值组合下的所有 i16 值。

`test-divide` 也已通过：对照全部 255 种除数和各自实际分子上界内的每个整数，验证保留的标量 Q32 实验，真机耗时约 10 秒。该实验的正确性不等于性能收益。

原始五模式日志、测试日志、二进制哈希见 [benchmarks/rk3399-requant.json](benchmarks/rk3399-requant.json)。

```sh
# 需与安装库匹配的开发头文件，或显式 -I 指定任务内头文件
cc -O3 -Wall -Wextra -Werror requant.c -Wl,-l:libjpeg.so.62 -lm -o requant
nice -n 10 taskset -c 4 ./requant test
nice -n 10 taskset -c 4 ./requant sparse
# 另测 flat / desktop / gradient / noise
```
