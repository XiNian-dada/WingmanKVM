# MS2130 EDID 调研记录（功能已移除）

当前版本已移除虚拟显示器分辨率与 EDID 管理功能，包括网页入口、厂商 HID 写入、启动时恢复和 USB 重新枚举后的重写。原因是当前硬件上的动态切换未通过实机验证，无法可靠地让被控机改变 HDMI 输出分辨率。

## 当前视频设置

```text
被控机 GPU：在被控机系统中选择桌面分辨率
  ↓ HDMI
MS2130 HDMI RX
  ↓ Capture：V4L2/UVC 采集输出尺寸与帧率
MJPEG 或 H.264/WebRTC
  ↓ Viewer：适应窗口、1:1 像素、填满窗口、全屏
网页
```

网页中的“采集输出尺寸”只改变采集和传输的视频大小。例如，采集 1280×720 不代表被控机桌面已经从 1920×1080 切换为 1280×720。设备默认选项使用采集卡当前的视频尺寸；可用格式与实际尺寸以采集卡返回结果为准。

画面缩放只影响浏览器显示，不改变 HDMI 输出或采集格式。

## 旧配置兼容

旧配置中的 `display`（包括 `virtual_monitor` 和 `control_device`）以及 `video.follow_display` 会被忽略，保存配置时不再输出这些字段。原有采集设备、固定宽高、帧率和编码设置继续保留；旧 Native 配置若未指定宽高，则使用采集卡当前的视频尺寸。

升级后的服务不会再接管 EDID，也不会尝试写回未知的出厂数据。之前已经写入采集卡 RAM 的内容可能继续存在，直到采集卡掉电后由自身固件重新初始化。

## 历史实机结果

以下内容用于保留调研依据，不代表当前支持的功能：

- 设备为 `345f:2130` MS2130。厂商 HID Feature Report（XDATA `B5/B6`）能够访问易失 EDID RAM；这与标准 UVC/V4L2 采集格式设置不同。
- 写入严格 720p EDID 后能够完整回读。源端强制重探测也曾读到仅包含 1280×720 的新模式列表，但活动 framebuffer 和 HDMI RX 输入仍为 1920×1080。因此，重新读取 EDID 不等于切换当前输出模式。
- `F014 bit 4` 能中断采集卡 HDMI RX，但实测没有证明它能拉低被控机侧物理 HPD。`F015 bit 3` 等候选控制位也没有完成实际分辨率切换的验证。
- 2026-09-16，源端监测期间的两组 RX 控制序列未产生可观察的 DRM 热插拔事件。
- 2026-09-17，源端强制重探测期间，720p EDID 生效但当前输出保持 1080p；事务超时后恢复原 EDID，视频恢复正常。
- `F660–F663` 曾用于读取 HDMI RX 输入宽高，但不测量输入刷新率，不能据此证明 HDMI 输出为 60Hz。

如未来重新引入虚拟显示器功能，需要先验证物理 HPD、源端实际输出及失败恢复，再接入产品界面。现有视频采集、H.264/WebRTC、USB Gadget 和 GPIO 电源控制不依赖这项实验功能。
